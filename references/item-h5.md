# 物料：H5 手机互动页

type 是 `h5`。发到微信里点开就能看的手机网页，可以上下滑动翻页，按钮点了真能用。目前做好的版式是 `invite`，婚礼、寿宴、满月、年会、发布会的电子邀请都用它。门店微页面和报名页还没做，用户要的话先用海报加二维码代替。

和印刷版请柬共用同一套方向、配色、字体和插画，所以一份 spec 里可以同时放 invitation（印刷）、tablecard（桌号牌）和 h5（电子版），整套风格自动统一。

## 交付的东西

| 文件 | 说明 |
|---|---|
| `out/h5/<id>.html` | 单个文件，字体和图片都打包在里面，双击就能在浏览器里看。字体只保留页面上用到的字，一般三四百 KB |
| `out/h5/<id>-preview.png` | 所有屏连在一起的长图，先看这张检查效果，也可以直接发给用户确认 |
| `out/h5/<id>-links.md` | 每位宾客一条专属链接（有 batch 时才有） |
| `out/<id>-1-cover-h5.png` 等 | 每一屏单独的预览图，overview.png 里也有 |

## 每一屏

invite 版式按顺序出这几屏，没内容的屏自动跳过。

1. 封面：小标签、插画、大标题、主人名字、日期、"诚邀 某某"、向上滑动的提示
2. 邀请信：称呼、正文、落款
3. 时间地点：日期、各环节时间、倒计时、地点，下面三个按钮是一键导航、加入日历、复制地址
4. 当日流程：时间轴，只有写了 schedule 才出
5. 回执：结束语、回复是否出席的按钮、联系电话按钮

## 内容字段

| 字段 | 说明 |
|---|---|
| kicker | 封面小标签，"WEDDING INVITATION""寿 宴 邀 请" |
| title | 大标题，必填，可以用 `\n` 分两行 |
| host | 主人，"林知远 & 陈晚晴""周家儿孙" |
| when | `{"start": "2027-05-22T17:30", "end": "2027-05-22T21:00", "tz": "Asia/Shanghai"}`，倒计时和加入日历都靠它。end 不写默认三小时，tz 不写默认北京时间 |
| body | 邀请信正文，段落之间空一行 |
| details | 时间行，`[{"k": "迎宾", "v": "17:30"}]` |
| venue、address | 地点名称和详细地址，导航和复制地址用 |
| map | 可选，`{"lng": 120.13, "lat": 30.25}`，写了就按坐标导航，更准 |
| schedule | 可选，流程，`[{"time": "18:18", "what": "婚礼仪式", "note": "补充说明"}]` |
| rsvp | 回执说明，"请于 5 月 10 日前回复是否出席" |
| rsvp_url | 回执链接，用户自己建的腾讯问卷、金数据之类。没给就在按钮下留【回执链接】占位 |
| contacts | 可选，最多两个，`[{"label": "联系新郎", "phone": "138……"}]` |
| closing、date_line | 结束语和落款日期 |
| music | 可选，背景音乐文件路径（mp3），会复制到 h5 文件夹旁边。音乐版权要用户自己确认 |
| default_guest | 链接里没写名字时的称呼，默认"亲朋好友" |
| invite_line、salutation | 封面和邀请信的称呼句式，默认"诚邀 {guest}"和"尊敬的 {guest}："，`{guest}` 会换成宾客称呼 |
| countdown_label | 倒计时前面的字，默认"距离婚礼还有"，寿宴改成"距离寿宴还有" |
| share_title、share_desc | 网页标题和描述，默认用主人加大标题 |

item 上还可以写 `publish_url`，就是这个文件放到网上以后的网址，写了以后 links.md 里就是能直接发的完整链接。

## 专属链接

batch 写宾客称呼列表，`"batch": ["王叔叔、王阿姨", "李老师"]`。不会生成一堆文件，只有一个 html，每位宾客的链接在后面加 `?to=称呼`，打开后封面和邀请信上就是对方的称呼。名字只当文字显示，不会被当成代码执行。

预览图用 batch 里的第一位宾客，正式文件在没带名字时显示 default_guest。

## 按钮怎么工作

- 一键导航：打开高德地图的网页，在手机上会尝试唤起高德 App。没有坐标时按"地点名称加地址"搜索
- 加入日历：下载一个 .ics 日历文件，提前一天提醒。微信内置浏览器不让下载，点了会提示用户点右上角在浏览器里打开
- 复制地址：复制地点和地址，弹出"地址已复制"
- 回复是否出席：跳到 rsvp_url
- 联系电话：拨号

## 放到网上

html 文件要放到一个能访问的网址才能发进微信。交付时把这几种办法告诉用户，让用户自己选。

- 有自己的网站或服务器：直接上传这个文件
- 国内的对象存储静态网站（腾讯云 COS、阿里云 OSS 这类）：在微信里打开最稳，用自己的域名时一般需要备案
- GitHub Pages、Vercel、Netlify：免费，但国内访问速度不稳定，微信里打开可能会慢或者出提示

放好以后在手机微信里自己点开试一遍，导航、复制、回执按钮都点一下。skill 没法替用户托管，也不要承诺"发出去就能打开"。

## 自动检查

pipeline 会把成品在 iPhone 14、iPhone SE、大屏安卓和电脑四种屏幕上打开，检查这些问题，结果并进 qa.json。

- 脚本有没有报错
- 页面能不能左右滑动（有东西超出屏幕宽度）
- 按钮是不是至少 44x44，手指好点
- 带 `?to=` 的称呼有没有换上
- 点"复制地址"有没有反馈
- 还没填链接的按钮
- 文件太大（超过 2.5 MB）

## 常见问题

- 长辈说字小：正文和按钮都按手机阅读字号排的，已经不小。还嫌小就把 body 删短，留给字号更多空间
- 想放婚纱照：art.image 放一张竖图，封面会用照片代替插画。照片会打包进文件，记得先压缩到 500 KB 以内
- 想要翻页动画更花哨：现在是淡入加轻微上移，够用也不晕。别加旋转、3D 翻转这类效果，老人手机会卡
